PROMPT 02 — NÍA MODE · EL HOTEL SE CONVIERTE EN LA INTERFAZ

IMPORTANTE: Este proyecto parte del mockup actual de Hotel Aura que acabas de construir.

NO rehagas Aura desde cero. NO cambies su identidad visual. NO reemplaces el diseño existente.

Vamos a evolucionar el mockup actual para crear una nueva capa de experiencia llamada conceptualmente “Nía Mode”.

---

1. OBJETIVO

Quiero transformar la experiencia de Aura desde un sitio web tradicional con un asistente flotante hacia una experiencia donde:

la conversación con Nía y la interfaz del hotel sean una misma experiencia.

La idea central es:

“No estoy hablando con un chatbot. Estoy interactuando con mi hotel.”

Nía sigue siendo la concierge digital de Aura.

Pero ahora, cuando el huésped conversa con ella, Aura responde visualmente.

El hotel se transforma, se desplaza, cambia de ambiente y revela contenido relacionado con aquello que el huésped está preguntando.

No quiero que esto parezca una aplicación de inteligencia artificial.

Quiero que parezca que el propio hotel cobra vida alrededor de Nía.

---

2. CONSERVAR AURA

Todo lo que funciona actualmente debe mantenerse:

- logo Aura
- identidad visual
- tipografía
- paleta
- fotografía
- navegación
- habitaciones
- experiencias
- gastronomía
- bienestar
- destino
- footer
- lenguaje editorial
- estética boutique caribeña
- sensación sofisticada, íntima y serena

NO rediseñar Aura.

No introducir:

- estética futurista
- neón
- hologramas
- dashboards de IA
- estética SaaS
- visuales tecnológicos
- exceso de glassmorphism
- gradientes artificiales
- interfaces que parezcan software empresarial

Aura sigue siendo un hotel.

Nía es la forma inteligente y natural de descubrirlo.

---

3. NÍA NO DEBE SENTIRSE COMO UN “CHATBOT”

Este principio es fundamental.

No quiero:

chat + página web

Quiero:

conversación → interpretación → transformación visual → contenido → acción

Nía debe actuar como una concierge que físicamente guía al huésped por las diferentes partes de Aura.

La interfaz es su lenguaje visual.

---

4. EL CONCEPTO FUNDAMENTAL

Utilizar esta lógica para toda la experiencia:

INTENCIÓN → ESTADO → AMBIENTE → CONTENIDO → ACCIÓN

Ejemplo:

Usuario:

“Muéstrame las habitaciones.”

Nía interpreta la intención.

↓

Aura entra en estado HABITACIONES.

↓

El ambiente visual cambia.

↓

Aparecen las habitaciones.

↓

El usuario puede explorar y elegir una.

La conversación y la interfaz son una sola interacción.

---

5. MODO TRADICIONAL

Al entrar al sitio, Aura debe seguir funcionando como el sitio actual.

El usuario puede:

- navegar
- hacer scroll
- explorar habitaciones
- ver experiencias
- conocer Brasa
- conocer bienestar
- reservar

Nía permanece disponible como concierge.

---

6. ENTRAR EN NÍA MODE

Cuando el usuario pulsa:

“Hablar con Nía”

no quiero que parezca que se abre una aplicación distinta.

No crear una pantalla independiente de chatbot.

En cambio:

la interfaz empieza a reaccionar.

Nía aparece y dice:

“Hola. ¿Qué te gustaría descubrir de Aura?”

Sugerencias:

- Ver habitaciones
- Descubrir experiencias
- Conocer Brasa
- Planear mi estadía

A partir de aquí, las respuestas de Nía pueden transformar visualmente el sitio.

---

7. ANIMACIÓN: PRINCIPIO FUNDAMENTAL

Las animaciones NO son decoración.

Son parte de la narrativa.

Cada vez que Nía interpreta una intención y muestra contenido, debe producirse una transición espacial y visual.

El usuario debe sentir:

“Nía está llevándome allí.”

No simplemente:

“Nía abrió una card.”

Utilizar como lenguaje general:

CONVERSACIÓN → TRANSICIÓN → CAMBIO DE AMBIENTE → CONTENIDO → ACCIÓN

---

8. LENGUAJE DE ANIMACIÓN

La experiencia debe sentirse:

editorial + cinematográfica + sofisticada + serena + espacial

Preferir:

- crossfade
- parallax
- cambios suaves de escala
- desplazamientos lentos
- capas de profundidad
- imágenes superpuestas
- opacity progresiva
- desplazamiento horizontal
- desplazamiento vertical
- fotografías que entran lentamente
- fotografías que desaparecen lentamente
- contenido que aparece progresivamente

Las animaciones deben sentirse caras y deliberadas, no llamativas.

Evitar:

- rebotes
- flashes
- zooms agresivos
- movimientos rápidos
- elementos que vuelen por la pantalla
- transiciones tipo presentación
- efectos tecnológicos
- animaciones que parezcan una aplicación SaaS

Utilizar como referencia de timing:

- transiciones principales: aproximadamente 600–1200 ms
- desplazamientos: suaves y con easing natural
- parallax: muy sutil
- cambios de opacity: progresivos
- escala: mínima y elegante

Estos valores son una referencia de comportamiento, no una obligación técnica rígida.

---

9. FOTOGRAFÍA COMO ATMÓSFERA

Este es uno de los elementos más importantes.

Cuando Nía muestre una experiencia o una parte del hotel, utilizar una fotografía de gran formato como capa ambiental.

La fotografía puede ocupar gran parte o toda la pantalla detrás del contenido.

Debe aparecer mediante:

opacity + crossfade + movimiento/parallax

No cambiar de fotografía bruscamente.

La fotografía inicialmente puede aparecer casi imperceptible y aumentar lentamente su presencia.

El contenido textual permanece legible sobre ella.

La fotografía funciona como una atmósfera, no como un simple background.

---

10. PARALLAX Y PROFUNDIDAD

Cuando aparezcan galerías o fotografías de gran formato, utilizar diferentes capas de profundidad.

Por ejemplo:

Fondo:
fotografía ambiental.

Capa intermedia:
fotografías secundarias desplazándose ligeramente a otra velocidad.

Primer plano:
títulos, información, botones y elementos de Nía.

Cada capa debe tener una velocidad de movimiento ligeramente diferente.

El efecto debe ser sutil.

El objetivo es crear sensación de profundidad y espacio.

No convertirlo en un efecto de parallax exagerado.

---

11. GALERÍAS

No mostrar las galerías simplemente como grids estáticos.

Cuando Nía lleve al usuario a una categoría visual, utilizar:

- imágenes grandes
- tarjetas con profundidad
- desplazamiento horizontal o vertical
- parallax
- crossfade
- superposición de fotografías
- cambios suaves de escala
- aparición progresiva de información

Las fotografías deben ser protagonistas.

El usuario debe sentir que está recorriendo el hotel, no navegando un catálogo.

---

12. ESTADO — HABITACIONES

Cuando el usuario diga:

“Muéstrame las habitaciones.”

Nía responde:

“Claro. Vamos a verlas.”

Entonces comienza una transición cinematográfica.

Secuencia:

1. La conversación de Nía permanece visible.

2. El contenido actual comienza a desplazarse suavemente.

3. Aparece una fotografía de habitación / terraza / mar como fondo ambiental.

4. La fotografía entra mediante crossfade + opacity.

5. La fotografía comienza un movimiento parallax extremadamente sutil.

6. Aparecen progresivamente:

- Habitación Deluxe
- Habitación Vista al Mar
- Suite Vista al Mar

7. Las imágenes pueden organizarse horizontalmente para crear una galería exploratoria.

8. Al seleccionar una habitación:

- aumenta ligeramente su escala
- gana protagonismo
- las demás disminuyen ligeramente su presencia
- aparece la información

9. Nía acompaña:

“Si buscas algo especial para una escapada en pareja, te recomendaría la Vista al Mar.”

Acciones:

“Ver esta habitación”

“Reservarla”

---

13. ESTADO — GASTRONOMÍA

Usuario:

“¿Dónde puedo cenar?”

Nía:

“Te llevaría a Brasa.”

La interfaz comienza a transformarse.

El contenido anterior pierde protagonismo.

Aparece progresivamente una fotografía de Brasa:

- fuego
- terraza
- mesa
- mar
- gastronomía

Utilizar:

crossfade + opacity + parallax

La fotografía puede adquirir un tono ligeramente más cálido, pero sin modificar artificialmente la identidad de Aura.

Aparece:

Brasa

“Cocina a fuego abierto en la terraza.”

Acción:

“Reservar mesa”

Nía:

“Brasa es nuestra cocina frente al agua. Si quieres, puedo reservarte una mesa para esta noche.”

---

14. ESTADO — ATARDECER

Usuario:

“Quiero algo especial para el atardecer.”

Nía:

“Entonces tengo una idea.”

Este debe ser uno de los momentos más cinematográficos del prototipo.

Secuencia:

1. Pausa breve.

2. El contenido anterior comienza a desaparecer lentamente.

3. El fondo empieza a cambiar.

4. Aparece una fotografía del mar al atardecer con baja opacidad.

5. La fotografía aumenta progresivamente su presencia.

6. Se mueve con un parallax muy lento.

7. Las capas anteriores se desplazan suavemente hacia fuera.

8. Aparece:

Navegación al atardecer

“Dos horas en el agua, con champaña.”

9. Nía aparece integrada en la composición:

“Dos horas en el agua, justo cuando el sol comienza a bajar. ¿Quieres que la agregue a tu estadía?”

10. Aparece:

“Agregar a mi estadía”

La sensación buscada es:

“Nía acaba de abrir una ventana hacia esa experiencia.”

---

15. ESTADO — BIENESTAR

Usuario:

“¿Y si quiero relajarme?”

Nía:

“Tengo algo para ti.”

La interfaz transiciona hacia Bienestar.

El fondo cambia mediante:

crossfade + opacity + parallax

Utilizar imágenes de:

- tratamientos
- naturaleza
- agua
- yoga
- espacios abiertos

El movimiento debe ser todavía más lento y sereno.

Mostrar:

Spa y bienestar

“Tratamientos al aire libre y yoga al amanecer.”

Acción:

“Reservar un ritual”

---

16. ESTADO — PLANIFICAR MI ESTADÍA

Usuario:

“Quiero planificar mi estadía.”

Nía comienza a construir una composición visual:

Tu estadía en Aura

Habitación
+
Cena en Brasa
+
Navegación al atardecer
+
Spa

Cada elemento puede aparecer progresivamente.

Utilizar pequeñas transiciones de:

- opacity
- scale
- desplazamiento

Las experiencias seleccionadas pueden quedar visualmente “ancladas” como parte del itinerario.

No crear un dashboard.

Debe sentirse como una composición editorial de la estadía.

Nía:

“Puedo ayudarte a armar una estadía a tu medida.”

---

17. ESTADO — RESERVAR

Cuando el usuario diga:

“Quiero reservar.”

La experiencia debe converger naturalmente hacia la reserva.

Mostrar:

- fechas
- huéspedes
- habitación
- experiencias seleccionadas
- precio estimado
- confirmación

Mantener el lenguaje visual de Aura.

No crear un checkout genérico de e-commerce.

Debe sentirse como:

“Nía ayudándome a organizar mi estadía.”

---

18. NÍA SIEMPRE ESTÁ PRESENTE

Nía no desaparece cuando cambia el estado.

Su presencia puede evolucionar:

- widget
- panel contextual
- mensaje integrado
- avatar + texto
- pequeño elemento flotante

Pero debe ser discreta.

Aura sigue siendo el protagonista.

Nía es quien ayuda al huésped a descubrirlo.

No hacer que el avatar de Nía ocupe más protagonismo que las fotografías y espacios del hotel.

---

19. CONTINUIDAD ESPACIAL

El usuario nunca debe sentir que cambió de página.

Debe sentir:

“Sigo dentro de Aura, pero Aura está reaccionando a lo que estoy diciendo.”

Las diferentes experiencias deben sentirse como espacios conectados de un mismo hotel.

Las transiciones deben mantener continuidad visual entre:

habitaciones → gastronomía → experiencias → bienestar → reserva.

---

20. DEMO INTERACTIVO

No necesito inteligencia artificial real ni APIs todavía.

Crear un prototipo funcional mediante:

- quick actions
- mensajes predefinidos
- estados internos
- respuestas simuladas
- botones

Lo importante es poder demostrar claramente:

“Le hablo a Nía y el hotel responde.”

- desktop
- tablet
- mobile

En mobile adaptar las composiciones.

Mantener:

- fotografía
- conversación

- sensación premium

---

24. CRITERIO DE ÉXITO

El resultado debe hacer que una persona que nunca haya visto el proyecto entienda inmediatamente:

“Nía no es un chatbot pegado a una página web.”

“Nía está guiando la experiencia digital del hotel.”

Y, sobre todo:

“Le hablo y el hotel cambia.”

Pero sin perder:

“Estoy en Aura.”

---

Trabaja sobre el mockup actual de Aura.

No empieces nuevamente desde cero.

Conserva todo lo que ya funciona.

Añade Nía Mode como una capa de interacción, estados visuales, fotografía ambiental y animación.

Prioriza especialmente:

1. la transición entre estados;
2. el parallax;
3. el crossfade de fotografías;
4. las fotografías ambientales con opacity;
5. la sensación de profundidad;
6. la continuidad espacial;
7. la integración de Nía con el contenido;
